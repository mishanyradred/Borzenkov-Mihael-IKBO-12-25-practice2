# Практическая работа № 2 · Вариант 3

Михаил Борзенков, ИКБО-12-25

CLI строит граф зависимостей выбранной версии npm-пакета. Он читает
JSON-метаданные реестра по HTTP с помощью стандартной библиотеки Python.
Обход в ширину реализован рекурсией по слоям. Результат сохраняется как
D2 и SVG. По запросу программа также печатает ASCII-дерево.

## Запуск и тесты

Требуется Python 3.10 или новее. Для визуализации установите
[D2 CLI](https://d2lang.com/tour/install/) и добавьте его в `PATH`.
На macOS D2 можно установить командой `brew install d2`.
Проект запускается из исходников без сборки.

```sh
./run.sh --help
./run.sh test -v
```

## Параметры

| Опция | Назначение |
| --- | --- |
| `--package ИМЯ` | Обязательное имя npm-пакета, включая форму `@scope/name`. В тестовом режиме используются заглавные латинские буквы. |
| `--repository ИСТОЧНИК` | Обязательный HTTP(S)-адрес npm-реестра или путь к JSON-файлу в тестовом режиме. |
| `--test` | Читать тестовый граф из локального JSON. |
| `--version X.Y.Z` | Обязательная точная версия корневого пакета, включая SemVer prerelease и build metadata. Тестовые вершины не имеют версий. |
| `--ascii` | Печатать ASCII-дерево. Метка `[seen]` указывает на ранее показанную вершину. |
| `--max-depth N` | Неотрицательная максимальная глубина. При `0` в граф входит только корень, при `1` также его прямые зависимости. По умолчанию ограничения нет. |
| `--exclude СТРОКА` | Исключить пакеты, чьё имя содержит заданную подстроку с учётом регистра. Обход через исключённые вершины прекращается. При исключении корня граф пуст. |
| `--output ПАПКА` | Каталог для `graph.d2` и `graph.svg`. По умолчанию используется `output/`. |
| `--no-open` | Сохранить SVG без открытия окна. По умолчанию файл открывается в системном просмотрщике или браузере. |

Скрипт `run.sh` переключается в корень проекта. Относительные пути
в параметрах отсчитываются от этого каталога. Ошибки аргументов дают код 2.
Ошибки чтения метаданных или рендера дают код 1.

## Тестовый репозиторий

Формат представляет собой JSON-объект с массивом соседей для каждой
вершины. Например, `{"A": ["B"], "B": []}`. Все соседи должны быть
объявлены. В примере ниже есть цикл `A → B → D → A`, общая зависимость
`D` и изолированная вершина `G`.

```sh
./run.sh --test --repository tests/fixtures/repository.json \
  --package A --version 1.0.0 --ascii --no-open --output output/test
./run.sh --test --repository tests/fixtures/repository.json \
  --package A --version 1.0.0 --max-depth 1 --exclude C \
  --ascii --no-open --output output/test-filtered
./run.sh --test --repository tests/fixtures/repository.json \
  --package G --version 1.0.0 --ascii --no-open --output output/test-isolated
```

В первом запуске обход открывает вершины в порядке `A, B, C, D, E`.
Во втором остаётся ребро `A → B`. В третьем граф состоит из одной вершины.
Рёбра к ранее найденным вершинам сохраняются. Каждая пара «имя и версия»
раскрывается один раз на минимальной глубине.

## История этапов

`git log --oneline --reverse` показывает пять этапов. Чтобы
воспроизвести промежуточный этап, добавьте отдельное рабочее дерево
командой `git worktree add --detach ПУТЬ ХЕШ` и запускайте его `run.sh`.

1. `7623266` печатает семь параметров как `ключ=значение`.
   Тесты демонстрируют ошибки для всех параметров.
2. `84d2593` выводит прямые зависимости и их диапазоны версий.
   Для `is-odd@3.0.1` ожидается `is-number: ^6.0.0`.
3. `3d7189d` выводит список смежности. Используйте команды тестового
   репозитория выше, опустив `--no-open` и `--output` с его значением.
4. `a58bf2e` поддерживает режим `--reverse` для конечного тестового
   репозитория. Программа разворачивает рёбра и запускает тот же BFS.
5. Последний коммит сохраняет D2 и SVG и поддерживает ASCII-дерево.

Для проверки этапа 4 выполните из соответствующего рабочего дерева:

```sh
./run.sh --test --repository tests/fixtures/repository.json \
  --package D --version 1.0.0 --reverse
```

Ожидаемый порядок: `B, C, A, F`. При `--max-depth 1` остаются `B, C`,
при `--exclude C` остаются `B, A`. Для `G` список пуст.

## Три визуализации и сравнение с npm

```sh
for item in is-even@1.0.0 is-odd@3.0.1 is-number@7.0.0; do
  name=${item%@*}
  ./run.sh --package "$name" --version "${item##*@}" \
    --repository https://registry.npmjs.org --ascii --output "output/$name"
done
```

Получены три SVG. При сравнении с `npm ls --all --package-lock-only`
(npm 11.20.0) совпали версии всех вершин и направления всех рёбер.

| Корень | Дерево npm от выбранного корня | Вершины / рёбра |
| --- | --- | --- |
| `is-even@1.0.0` | `is-even@1.0.0 → is-odd@0.1.2 → is-number@3.0.0 → kind-of@3.2.2 → is-buffer@1.1.6` | 5 / 4 |
| `is-odd@3.0.1` | `is-odd@3.0.1 → is-number@6.0.0` | 2 / 1 |
| `is-number@7.0.0` | `is-number@7.0.0` | 1 / 0 |

Для воспроизведения сравнения создайте отдельный временный проект для
каждого пакета. Замените аргумент установки нужным именем и версией.

```sh
comparison_dir=$(mktemp -d)
(
  cd "$comparison_dir"
  npm init -y
  npm install --package-lock-only --ignore-scripts --no-audit --no-fund \
    --registry https://registry.npmjs.org --save-exact is-even@1.0.0
  npm ls --all --package-lock-only
)
```

`npm ls` добавляет сверху временный проект. SVG начинается с выбранного
пакета. Программа читает `dependencies` и `optionalDependencies`, выбирает
наибольшую подходящую версию по SemVer и учитывает теги и npm-алиасы.
Поддерживаются точные версии, неполные версии, шаблоны, `^`, `~`,
сравнения, диапазоны через дефис и `||`. Ссылки Git, URL и локальные
зависимости выходят за рамки реестрового анализа.

В более сложных проектах npm учитывает lock-файл, `peerDependencies`,
платформенные ограничения и дедупликацию дерева установки. Программа
показывает граф деклараций реестра, поэтому такие проекты могут давать
другие результаты. См. [формат package.json](https://docs.npmjs.com/files/package.json/)
и [описание npm ls](https://docs.npmjs.com/cli/v11/commands/npm-ls/).
